## Executive summary

1. **No browser documents or ships eye/face tracking for web pages.** The W3C WebXR spec has no such module; the "expression-tracking" draft (Meta editor) dates from 2022-12 and had a Nov 2025 face-to-face discussion without an API decision. (VERIFIED draft; implementation absence REPORTED.)
2. **One real lead:** Meta's emulator IWER 2.5.0 models a WebXR `gaze` input source (`gaze-tracking` / `eye-tracking` features, profile `eye-gaze`), and Meta's IWSDK 1.0 (2026-09-24) uses gaze-and-pinch. Whether Quest Browser on a Quest Pro gives a page real gaze is **UNVERIFIED**; a 5-minute probe settles it.
3. Even if present, that source is a **single combined ray**: no per-eye data, **no eyelids, no face**. Blinks stay procedural.
4. **Face expressions need a bridge.** Quest Pro face data (63/70 weights, `XR_FB_face_tracking(2)`) is reachable only by an OpenXR app on Meta's runtime; Steam Link / ALVR / Virtual Desktop relay it to the PC as OSC, from where a small Node tool can feed the page by WebSocket. Recommended real-data route: Quest Pro -> Steam Link -> SteamVR -> desktop Chrome + local bridge.
5. **Steam Frame has eye tracking, no face tracking.** Official API: one combined gaze (`XR_EXT_eye_gaze_interaction`, OpenVR `eyetracking`). Per-eye gaze and eyelids exist only in a private on-device format that community MIT tools read (REPORTED, 1-2 weeks old, fragile). Valve points to the expansion port for third-party face tracking.
6. **Our avatar is morph-only with no face/eye/jaw bones.** It has `blink_left/right`, `look_left/right/up/down` and 26 identity face targets; both eyes share the same look weights and the blink is identical on both sides, so per-eye tracking needs a small `eyelife` extension.
7. **MakeHuman ships 34 CC0 expression-unit targets** (eyelids, brows, mouth open/pucker/compress/corner puller, nose...). Roughly 16 of the ~20 MVP morphs can come from them after a visual check; `cheekPuff`, `tongueOut`, jaw sideways, `mouthClose` and per-eye look must be generated by project code.
8. **Use ARKit-52 camelCase names for new morphs**, keep `blink_*`/`look_*` as aliases; visemes and VRM expressions as weight recipes, not extra shape keys.
9. **Performance trap, verified in three r170 source:** the morph shader loops all targets per vertex per render pass; split the head into its own mesh before driving ~25 face morphs through a stereo mirror.
10. **Testing without hardware:** IWER emulates the gaze source but **not** face data; face tests run on replay/synthetic fixtures through our own `FaceFrame` layer (M0). Privacy: off by default, local only, never stored.
